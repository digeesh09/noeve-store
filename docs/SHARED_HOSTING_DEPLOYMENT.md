# Noeve — Shared Hosting Deployment Guide

Deploying a modern JavaScript monorepo (Next.js + NestJS) to traditional shared Linux hosting (like cPanel, Plesk, Hostinger, GoDaddy) is possible, but requires specific features from your hosting provider. 

Unlike VPS hosting, **shared hosting does not support Docker**. You must deploy the applications natively as Node.js apps.

## Prerequisites for Shared Hosting

To host Noeve on a shared host, your provider **must** support:
1. **Node.js Setup** (usually via "Setup Node.js App" in cPanel / Phusion Passenger).
2. **PostgreSQL Database** (If they only offer MySQL, you must use a free external database like [Supabase](https://supabase.com) or [Neon](https://neon.tech)).
3. **Terminal / SSH Access** (Highly recommended for running database migrations).

*Note: Redis and MinIO are typically not available on shared hosting. You will need external services like [Upstash](https://upstash.com) for Redis, and standard AWS S3 or Cloudflare R2 for media storage.*

## Step 1: Prepare the Build Locally

Shared hosting servers often have limited CPU and memory, which can crash during the build process. It is highly recommended to **build the apps on your local machine** and upload the built files.

### 1. Build the API
```bash
# In your local terminal
cd Code
pnpm install
npx prisma generate
pnpm --filter @noeve/api build
```

### 2. Build the Web Store
*Ensure `output: 'standalone'` is set in `apps/web-store/next.config.ts`.*
```bash
# In your local terminal
export NEXT_PUBLIC_API_URL=https://api.noeve.store/v1
pnpm --filter @noeve/web-store build
```

### 3. Build the Web Admin
*Ensure `output: 'standalone'` is set in `apps/web-admin/next.config.ts`.*
```bash
export NEXT_PUBLIC_API_URL=https://api.noeve.store/v1
pnpm --filter @noeve/web-admin build
```

## Step 2: Upload Files via cPanel/FTP

You will set up three separate Node.js applications in your control panel. Create three folders in your hosting root (e.g., outside `public_html` for security):
- `~/noeve-api`
- `~/noeve-store`
- `~/noeve-admin`

### API Upload (`~/noeve-api`)
Upload the following from `apps/api/`:
- The `dist/` folder.
- The `node_modules/` folder (or run `npm install --production` via SSH on the server).
- The `prisma/` folder.
- Create a `.env` file with your database URL, JWT secret, etc.

### Web Store Upload (`~/noeve-store`)
Because we use Next.js standalone mode, you only need to upload the standalone output:
1. Copy everything inside `apps/web-store/.next/standalone/` to `~/noeve-store`.
2. Copy `apps/web-store/public/` into `~/noeve-store/public/`.
3. Copy `apps/web-store/.next/static/` into `~/noeve-store/.next/static/`.
4. Create a `.env.production` file here with your environment variables.

### Web Admin Upload (`~/noeve-admin`)
Follow the exact same standalone upload steps as the Web Store, but from `apps/web-admin/` to `~/noeve-admin`.

---

## Step 3: Setup Node.js Apps in cPanel

Go to your hosting control panel and find the **"Setup Node.js App"** (or similar) section. You will create three apps.

### 1. The NestJS API (`api.noeve.store`)
- **Node.js Version:** 20 (or 18 minimum)
- **Application Mode:** Production
- **Application Root:** `noeve-api`
- **Application URL:** `api.noeve.store`
- **Application Startup File:** `dist/main.js`

### 2. The Web Store (`noeve.store`)
- **Node.js Version:** 20 (or 18 minimum)
- **Application Mode:** Production
- **Application Root:** `noeve-store`
- **Application URL:** `noeve.store`
- **Application Startup File:** `server.js` (This file is generated by the standalone build).

### 3. The Web Admin (`admin.noeve.store`)
- **Node.js Version:** 20 (or 18 minimum)
- **Application Mode:** Production
- **Application Root:** `noeve-admin`
- **Application URL:** `admin.noeve.store`
- **Application Startup File:** `server.js`

---

## Step 4: Database Migrations

You must apply your Prisma schema to your PostgreSQL database.
If you have SSH access to your cPanel account:

```bash
cd ~/noeve-api
npx prisma migrate deploy
```

*(If you are using an external database like Supabase, you can simply run this command from your local machine, pointing your local `.env` to the remote Supabase database URL).*

## Step 5: Start & Restart Apps

In your cPanel "Setup Node.js App" interface, click **Start** or **Restart** for all three applications. 

Your web server (Apache/LiteSpeed provided by the host) will automatically route traffic from `noeve.store` to your internal Node.js process using Phusion Passenger or a reverse proxy.
